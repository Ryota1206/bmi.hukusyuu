セットアップ（最初の1回だけ）

Docker Desktop を起動してから始めてください。

  1. 1

    リポジトリを取ってくる

    まだ clone していない人:

    git clone git@github.com:posse-ap/posse2-hackathon-202609-teamF.git
cd posse2-hackathon-202609-teamF
git switch develop

    空の状態で clone 済みの人:

    git fetch origin
git switch develop
    Tip

    git pull だけだと「追跡情報がない」と怒られることがあります。上の2行が確実です。

  2. 2

    設定ファイルを作る

    copy config.php.example config.php

    Mac の人は cp config.php.example config.php

    中身は変えなくて大丈夫です。このファイルは Git に入らないので、コミットもされません。

  3. 3

    起動する

    docker compose up -d

    初回はダウンロードとビルドで3〜5分かかります。そのあと MySQL の初期化に30秒ほど。

  4. 4

    動いているか確認する

    http://localhost:8080 を開いて、 「環境構築チェック」が 4つすべて緑になればOKです。

    「DB接続」がNGなら、30秒待ってページを再読み込みしてください。MySQL の起動待ちです。

  5. 5

    ログインしてみる

    メールアドレスuser1@example.com 〜 user10@example.com
    パスワードpassword1234

    user3@example.com（高橋あおいさん）で入ると、あいさつにリアクションが付いた状態が見られます。

確認

npm install はありません。 Tailwind は CDN から読み込んでいるので、ビルド作業は一切不要です。ファイルを保存してブラウザを再読み込みすれば、すぐ反映されます。

VSCode のターミナル

このページのコマンドは、すべて VSCode の中で打てます。黒い画面を別に開く必要はありません。

開き方

  1. VSCode で posse2-hackathon-202609-teamF フォルダを開く
  2. 上のメニュー ターミナル → 新しいターミナル
  3. 画面の下半分に文字入力エリアが出ます。そこがターミナルです

ショートカットは Ctrl + Shift + @（Mac は Control + Shift + `）

使い方

  • コマンドを貼って Enter。1行ずつです
  • cd は打たなくていい — VSCode で開いているフォルダが最初から現在位置になっています
  • パスワードを聞かれたら入力 → Enter。打っても文字は表示されません（そういう仕様です）
よくある勘違い

コマンドを打ったあと、何も表示されずにプロンプトが戻ってくることがあります。それは成功です。Git は成功したとき静かなことが多いです。

作業の流れ（毎回この順番）

  1. 1

    最新にして、作業用ブランチを作る

    git switch develop
git pull
git switch -c feature/hobby-view

    feature/ のあとは自分が作る画面の名前にしてください。 -view を付けておくと、バック側の作業と区別できます。

    重要

    この3行はセットです。 git pull を飛ばすと古い状態から作業を始めてしまい、あとで面倒になります。前回のブランチから枝分かれさせるのもダメです。

  2. 2

    ファイルを1つだけ編集する

    担当の src/views/〇〇_content.php だけを開きます。保存したらブラウザを再読み込みして確認。

  3. 3

    何を触ったか確認する

    git status

    自分が触ったファイルだけが並んでいるか、必ず目で見てください。 見覚えのないファイルがあれば、そこで止めて相談してください。

  4. 4

    コミットして push する

    git add .
git commit -m "輪の詳細画面のデザインを作成"
git push -u origin feature/hobby-view
    * [new branch] feature/hobby-view -> feature/hobby-view

    この [new branch] が出れば成功です。

  5. 5

    Pull Request を出す

    1. GitHub を開くと、黄色い帯に Compare & pull request が出ます
    2. 押す
    3. base が main になっていたら develop に変える ← ここだけ絶対
    4. 説明に「触ったファイル: src/views/hobby_content.php」と書く
    5. Create pull request
    間違えやすい

    base が main のままだと、発表用のブランチに直接入ってしまいます。押した時点では何も起きないので、次の画面で develop に変えてから「Create pull request」を押してください。

  6. 6

    マージされたら次へ

    git switch develop
git pull
git branch -d feature/hobby-view

    最後の行は、もう使わないブランチを手元から消すだけです。

ファイルの読み方

ファイルを開くと、先頭にこういうコメントが入っています。これが約束事です。

/**
 * 【このファイルで使える変数】これ以外は使えません
 *   $errors … エラーメッセージの配列。空なら何も表示しない
 *   $email  … 入力されたメールアドレス
 *
 * 【フォームの約束】name を変えないでください
 *   name="email" / name="password" / name="csrf_token"
 *
 * 【編集していい範囲】
 *   ✅ HTMLの構造・Tailwindのクラス・文章
 *   ❌ name属性 / 変数名 / PHPの処理
 */

ここに書かれていない変数は使えません。 必要な情報が足りないときは、自分で作らずバック担当に相談してください。

覚える PHP はこの3つだけ

// 表示する（h() は必須。忘れると脆弱性になります）
<?= h($変数) ?>

// 出す・出さない
<?php if ($errors): ?> ... <?php endif; ?>

// 繰り返す
<?php foreach ($messages as $msg): ?>
  <p><?= h($msg['body']) ?></p>
<?php endforeach; ?>

あとは普通に HTML を書いて、Tailwind のクラスで見た目を作るだけです。

消してはいけないもの

デザインを整えるときに、うっかり消しやすいものが2つあります。消すと動かなくなり、原因も分かりにくいので気をつけてください。

  • name="email" のような name属性 — これでデータが送られています
  • <input type="hidden" name="csrf_token" ...> — 消すと「不正なリクエストです」で全部弾かれます

色は決まったものを使う

用途クラス
メインの色bg-primary text-primary
カードglass-panel rounded-2xl p-6 shadow-sm
水滴ボタンripple rounded-drop bg-primary text-on-primary
本文の色text-on-surface / 補足は text-on-surface-variant
趣味タグの色hobby_color() が自動で決めます。自分で色を選ばないこと

bg-blue-600 のような直書きはしないでください。あとで全体の色を変えられなくなります。 見本は src/views/hobby_content.php です。

AI の使い方

AI に聞くのは大歓迎です。ただしそのまま貼るのはNG。レビューで「ここ何してるの?」と聞かれて答えられないコードは、マージできません。

そのまま使える聞き方

これから src/views/hobby_content.php を編集します。

・スタイルは Tailwind CSS v4 のクラスで書いてください（@apply は使えません）
・メインの色は bg-primary / text-primary を使ってください
・使える変数はファイル先頭のコメントに書いてあるものだけです
・PHPの処理は書かないでください（HTMLとクラスだけ）
・新しいファイルやフォルダは作らないでください
・変更した行だけ教えてください。ファイル全体は出さないでください
・name属性と csrf_token の hidden は消さないでください

（ここにファイルの中身を、先頭のコメントごと貼る）
Tip

Claude と GitHub Copilot は、このプロジェクトのルールを自動で読みます（CLAUDE.md と .github/copilot-instructions.md があるため）。 ブラウザの ChatGPT や Gemini は読まないので、AGENTS.md の手順に従って先にルールを貼ってください。

AI がやりがちな失敗

実際に起きる順に並べています。

  1. 重大
    ファイル全体を書き直して返す

    それを丸ごと貼ると、他の人が同じファイルに入れた変更が消えます。「変更した行だけ教えて」と毎回言ってください。

  2. 重大
    name属性と csrf_token を消す

    見た目は綺麗になるのに、送信しても何も保存されなくなります。デザインを整えてもらったあとは、必ず動かして確認してください。

  3. 重大
    config.php の中身を貼ってしまう

    データベースのパスワードが入っています。絶対に貼らないでください。

  4. 注意
    共通ファイルを書き換えようとする

    header.php や functions.php を「こう直しましょう」と平気で言ってきます。全員に影響するので、マージ前に必ず相談してください。

  5. 注意
    勝手に新しいファイルやフォルダを作る

    assets/ や helpers/ を増やしてきます。構成が崩れるので断ってください。

  6. 注意
    Laravel と React のコードを出してくる

    PHP と聞くと Route:: を、JavaScript と聞くと React を出します。「使えません、素のPHPで書き直して」と言えば直ります。

  7. 注意
    @apply や tailwind.config.js を提案する

    CDN版の Tailwind では動きません。クラスを直接 HTML に並べる形にしてもらってください。

統一のコツ

5人がそれぞれ AI に聞くと、同じことを5通りの書き方で作ってしまいます。 完成しているファイルを見本として一緒に貼ると揃います。 「hobby_content.php と同じ書き方で作ってください」と添えるだけで効きます。

困ったとき

出た文字・症状どうするか
Permission denied (publickey) GitHub に SSH 鍵を登録していません。エラー全文をチームに貼ってください（HTTPS でも clone できます）
Enter passphrase for key SSH 鍵のパスワードを聞かれています。入力して Enter（文字は表示されません）
CONFLICT そこで止めて全文を貼ってください。自分で解決しようとしないこと
! [rejected] GitHub 側に別の変更があります。止めて相談してください
port is already allocated 8080番が他で使われています。チームに相談（ポート番号を変えます）
「DB接続に失敗しました」 MySQL の起動待ちです。30秒待って再読み込み
「config.php が見つかりません」 セットアップの手順2をやり直してください
画面が真っ白 PHP の書き方が壊れています。<?php と ?> の対応、endif / endforeach の抜けを確認
CSSが効かない Ctrl + Shift + R で強制再読み込み
アイコンが出ない Google Fonts から読み込んでいます。ネット接続を確認してください
聞き方

相談するときは、①打ったコマンド ②エラー全文 ③やろうとしていたことの3つを貼ってください。「動きません」だけだと誰も助けられません。

絶対にやらないこと

これだけ守れば、取り返しのつかない事故は起きません。

  • ✕git push -f を使う — 他の人のコミットが消えます。エラーで困っても、これは使わないでください
  • ✕develop と main で直接作業する — 必ず feature/〇〇-view を切ってから
  • ✕config.php を AI に貼る・コミットする — パスワードが入っています

それ以外の失敗は、ほぼ全部あとから直せます。迷ったら push する前に聞いてください。 壊してから相談するより10倍楽です。
